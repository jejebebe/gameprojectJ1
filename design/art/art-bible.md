## 1. Visual Identity Statement

**한 줄 규칙: "배경은 포근하게, 플레이어가 상호작용하는 것은 또렷하게."**
놀이터는 Cat Isle처럼 맑고 아늑하게, 밟고·피하고·먹는 것은 한눈에 보이게.

### 원칙 1. 배경은 물러서고, 게임 요소는 앞으로 나온다
- 근거: 8~12세가 혼자 끝까지 깨려면 한 화면에서 위험과 발판을 바로 구분해야 한다 (브리프 "what they feel").
- 배경(하늘, 구름, 지붕, 물 반사): 채도 낮고 밝은 청록·하늘색, 대비 약하게.
- 발판·블록·가시·적·아이템: 배경보다 채도 또는 명도 대비가 확실히 높다. 형태는 단색 덩어리 + 음영 1톤 (재질별 한 단계 어두운 색, 섹션 5 음영 규칙).
- 외곽선 (개정 2026-10-28, 사용자 결정 — 제이 최종 그림 기준): 배경·지형·소품은 외곽선 없음. 캐릭터·적·보스는 제이처럼 검은 1px 외곽선을 쓴다. (이전 규칙:) 검은 외곽선은 쓰지 않는다. 예외 — 작아서 뭉개지는 가시와 작은 적(나는 적 등)에 한해 짙은 남색 외곽선을 허용한다 (사용자 결정 2026-10-28).
- 판단 기준: 배경 소품과 발판이 헷갈리면, 배경을 더 연하게·발판을 더 진하게 한다.

### 원칙 2. 색은 역할을 말한다
- 근거: 능력을 빼앗는 짜릿함은 무엇이 위험하고 무엇이 보상인지 즉시 읽힐 때 생긴다.
- 빨강 = 제이의 망토(영웅 색). 보라 = 적. 주황 = 적의 공격·불. 금색·노랑 = 보상(하트, 체크포인트). 청록·크림 = 안전한 지형. (개정 2026-10-28: 제이가 빨간 망토를 입으므로 적은 빨강에서 보라로 바뀌었다.)
- 게임 화면의 진한 빨강 `#D2373F`는 제이 전용이다. 배경의 따뜻한 포인트(차양, 지붕, 등대 줄무늬)는 복숭아·주황 톤(`#DF9F8F`, `#F0A040`)으로 낮춘다 (사용자 결정 2026-10-28). 위험물은 색만으로 구분하지 않는다 — 가시·적은 뾰족한 형태와 높은 명도 대비(필요하면 외곽선 예외)로 읽힌다.
- 판단 기준: 색 선택이 애매하면, 그 오브젝트가 해로운지 이로운지부터 정하고 그 역할 색을 고른다. 배경 소품이 위험물로 오해될 수 있으면 배경 쪽 채도를 낮춘다.

### 원칙 3. 통통하고 둥근 실루엣, 큰 눈
- 근거: 8~12세 대상, 제이와 적이 귀엽고 즉시 구별되어야 한다.
- 2등신, 큰 눈(색 반사점). 검은 양갈래 + 빨강 망토가 제이의 상징. 3/4 비대칭 포즈. 각진 블록 형태 금지 (개정 2026-10-28: 첫 기준 그림이 촌스럽다는 피드백).
- 360x320 게임 뷰에서 실루엣만으로 구분 가능해야 한다. 적 3종(걷기·점프·비행)은 실루엣부터 서로 다르다.
- 판단 기준: 디테일을 더할지 애매하면 실루엣이 더 분명해지는 쪽을 고르고, 작은 크기에서 뭉개지면 디테일을 뺀다.

### 그림 검수 기준
배경·지형·소품: 외곽선 없음 + 마스터 팔레트(30색). 캐릭터·적·보스: 검은 1px 외곽선 + 캐릭터 팔레트(`assets/art_src/palette/jei_character.gpl`, 32색, 제이 최종 그림에서 추출) (개정 2026-10-28) / 2등신 비율 / 게임 요소가 배경보다 대비 높음 / 캐릭터 좌우 대칭 금지 / 3px 넘는 직선 윤곽 금지 (곡선은 계단형). 하나라도 어기면 다시 그린다.

## 2. Mood & Atmosphere

모든 상태는 Cat Isle의 포근한 항구 마을 안에서 벌어진다. 레벨 테마는 제안이며 바꿀 수 있다.

| 상태 | 감정 목표 | 조명 | 키워드 | 에너지 | 분위기를 만드는 요소 |
|---|---|---|---|---|---|
| L1 "배우기" (제안: 아침 항구) | 안심, 호기심 | 아침, 차가운 쪽, 대비 가장 낮음 | 맑음·바닷바람·잔잔함 | 낮음 | 옅은 하늘색 하늘, 물 반사, 갈매기 |
| L2 "새 능력" (제안: 오후 지붕길) | 들뜸, 도전 | 한낮, 중간 온도, 대비 중간 | 쨍함·활기·높이 | 중간 | 청록 기와와 주황 줄무늬 차양, 빨래줄 |
| L3 "섞어 쓰기" (제안: 노을 등대 절벽) | 몰입, 자신감 | 노을, 따뜻함, 대비 높음 | 분홍 하늘·긴 그림자·바람 | 높음 | Cat Isle식 분홍·복숭아 노을, 빨강·흰색 줄무늬 등대 |
| 보스 "가시 두더지" (제안: 해 진 직후 등대 아래 동굴 입구) | 긴장하지만 무섭지 않음 | 저녁, 자주색 바탕에 등불 포인트 | 땅울림·흙먼지·등불 | 최고 | 흔들리는 등불, 흙 부스러기 파티클 |
| 피격 | 아차! (벌이 아니라 알림) | 순간 흰색 번쩍임 | 짧음·가벼움 | 순간 | 제이 흰색 깜빡임 2회, 화면 흔들림 2px |
| 사망 → 체크포인트 | 괜찮아, 다시 | 게임 화면 채도를 잠깐 낮춤 | 부드러움 | 낮음 | 원형으로 닫혔다 열리는 전환, 금색 깃발 강조 |
| 게임 오버 | 아쉽지만 다시 하고 싶음 | 짙은 남색 반투명 막 + 크림 패널 | 조용함·따뜻함 | 낮음 | 졸린 제이 일러스트, 빨간 리본 배너 |
| 클리어! | 해냈다! | 금빛, 대비 최고 | 반짝임·축제 | 최고 | 금색 방사형 빛, 빨간 리본 "클리어!", 색종이 |
| 메인 / 일시정지 / 레벨 선택 | 아늑함, 내 섬 | 아침 항구 배경을 흐리게 | 정돈됨·포근함 | 낮음 | 크림 둥근 패널, 금색 메달형 레벨 아이콘 |

- 공포 표현 금지: 순수 검정 화면, 빨간 화면 채움, 피 표현 없음.
- 두 상태를 나란히 놓고 썸네일로 봤을 때 시간대 색으로 구분되어야 한다.
- 사망 전환, 게임 오버 일러스트, 클리어 색종이 등 지금 게임에 없는 연출은 그림 방향만 정한 것이며, 구현 여부는 볼륨 결정 때 정한다.

## 3. Shape Language

**실루엣** (원칙 3)
- 제이: 둥근 2등신, 식별 표지는 양갈래 + 망토(후드 주름, 뒤로 퍼지는 끝단). 어떤 포즈에서도 양갈래가 보여야 한다.
- 화면에서 둥근 것 = 아군·보상·안전, 뾰족한 것 = 위험.
- 적은 원형 몸통 위에 위험 표지 하나만 붙여 특징을 딱 하나씩 준다.
  - 걷는 적: 낮고 넓은 반원 몸통 + 머리 위 뿔 1개
  - 점프하는 적: 세로로 긴 물방울형 + 아래쪽 용수철 다리
  - 나는 적: 작은 원 + 삼각 날개 2장 (남색 외곽선 허용 대상)
  - 보스 가시 두더지: 제이보다 확실히 큰 반구(스프라이트 72x60, 섹션 5) + 등에 부채꼴로 난 가시. 큰 앞발 삽 2개는 공격 예고 동작에 쓴다.
  - 적의 색은 섹션 4 (보라).

**위험물과 장식의 구분** (원칙 2)
- 가시와 적은 형태만으로 위험해 보여야 한다. 가시 = 톱니처럼 날카로운 삼각형 연속 + 남색 외곽선.
- 배경의 빨간 소품(차양, 등대, 지붕)은 둥근 모서리·직사각형·물결 형태만 쓴다. 날카로운 삼각형 금지.
- 검사: 흑백 썸네일로 봐도 가시와 적만 뾰족해야 한다.

**지형**
- 발판·블록: 모서리를 1px 둥글린 직사각형, 윗면은 밝은 1줄.
- 불타는 나무벽: 세로 판자 + 못 자국으로 일반 블록과 결이 다르게.
- 배경: 큰 덩어리, 낮은 디테일, 둥근 구름 위주.

**UI 문법** (Cat Isle 참고)
- 크림색 둥근 사각 패널 (모서리 반경 4px 이상)
- 제목 = 빨간 리본 배너 (양끝 V자로 갈라짐)
- 주요 버튼 = 짙은 남색 알약형 + 크림색 글자/아이콘 (현재 주황 메뉴 버튼은 아트 교체 때 바꾼다)
- 레벨·보상 표시 = 금색 원형 메달 + 빨간 끈
- 하트 HUD = 통통한 하트, 빈 하트는 남색 테두리만

**주연과 조연**
- 게임 요소(제이·적·발판)는 배경 소품보다 덩어리가 크고 단순하다.
- 배경 디테일은 게임 요소보다 작은 단위로 그린다.

## 4. Color System

하늘·청록·어두운 색은 Cat Isle 스크린샷 4장에서 실제로 많이 쓰인 색에 맞췄다 (사용자 결정 2026-10-28). 문서 전체의 "짙은 남색"은 아래 `#302030`(보랏빛 남색)을 뜻한다.

**주요 팔레트**

| 색 | Hex | 역할 |
|---|---|---|
| 하늘 | `#BFEFFF` (윗하늘·물 `#80DFFF`) | 배경 기본 (물러섬) |
| 항구 청록 | `#50AF9F` (짙은 쪽 `#408F9F`) | 안전한 지형, 기와 |
| 크림 | `#F6EEE4` | 발판 윗면, UI 패널 |
| 짙은 남색 | `#302030` (보조 `#404050`) | 음영 1톤, 외곽선 예외, 버튼, 제이 머리 |
| 망토 빨강 | `#D2373F` (음영 `#AF3050`) | 제이 망토·머리끈 (게임 화면에서 제이 전용), UI 리본 |
| 적 보라 | `#9060A8` (음영 `#6E4A6A`) | 적, 가시 끝, 보스 가시 (2026-10-28 추가) |
| 주의 주황 | `#F07A2A` | 적 공격, 불덩이 |
| 보상 금색 | `#E8B54A` | 하트, 체크포인트, 메달, 클리어 |

**의미별 사용**
- 위험: 보라 + 뾰족한 형태 (형태가 1차 신호), 적의 공격은 주황.
- 보상: 금색 + 둥근 형태 + 반짝임.
- 안전 지형: 청록 또는 크림.
- 능력 색 (아이콘 형태도 각각 다르게):
  - 불덩이: 주황 `#F07A2A` + 연노랑 심 `#FFF1B8`, 둥근 불꽃 모양
  - 높이 점프: 하늘 `#80DFFF` + 흰색, 위쪽 화살표 모양
  - 활공: 분홍 `#E89AC0`, 날개/잎사귀 모양

**레벨별 색 온도**
- L1: 차가움. 하늘·옅은 청록, 배경 채도 최저.
- L2: 중간. 하늘이 조금 진해지고 주황 차양이 늘어난다.
- L3: 따뜻함. 분홍 `#DF608F` ~ 복숭아 `#DF9F8F` 노을, 구름 `#EFDFDF`. 분홍 노을에 활공 망토(분홍)·보라 적이 묻히지 않도록 음영을 강화한다.
- 보스: 자주 `#6E4A6A` 바탕. 짙은 남색 외곽선이 묻히지 않도록 배경을 남색보다 어둡게 하지 않는다. 보스 가시 끝은 `#9060A8`; 보라가 자주 바탕에 묻히지 않도록 가시에는 크림 몸통 + 남색 외곽선을 유지한다.
- 어느 레벨이든 배경은 게임 요소보다 연하고 대비가 낮다 (원칙 1).

**UI 팔레트**
- 크림·짙은 남색·빨강·금색 4색 중심.
- 게임 화면과 다른 점: UI는 채도 높은 빨강을 자유롭게 쓴다. UI는 하단 조작 영역에 있어 위험 신호와 혼동되지 않는다. 상단 HUD 하트는 금색.

**색맹 대응**
- 빨강과 금색 (적록색맹): 하트·메달은 둥근 형태 + 반짝임, 위험물은 뾰족한 형태.
- 보라 위험물과 배경: 형태 규칙(섹션 3) + 남색 외곽선 + 명도 대비.
- 빨강 망토(제이)와 보라 적: 색이 비슷하게 보이는 색맹 유형에서도 실루엣(망토·양갈래 vs 뿔·물방울·날개)으로 구분된다.
- 하늘색 점프와 분홍 활공 (청황색맹): 아이콘 형태가 다르고 효과음도 다르게.
- 피격 = 흰색 번쩍임 + 효과음. 색 하나만으로 전달하는 정보는 없다.

**제한 마스터 팔레트** (30색 — 배경·지형·소품·UI용. 캐릭터·적·보스는 `assets/art_src/palette/jei_character.gpl` 32색, 개정 2026-10-28)
- 하늘·물: `#FFFFFF` `#EFFFFF` `#BFEFFF` `#80DFFF` `#3A9FC4`
- 청록·초록: `#AFDFDF` `#50AF9F` `#408F9F` `#1F5E66`
- 크림·돌: `#F6EEE4` `#E3DDD2` `#BDB4A8`
- 나무·흙: `#C98A5A` `#8A5A3C` `#5A3A2C`
- 따뜻한 위험색: `#FFF1B8` `#F0A040` `#F07A2A` `#D2373F` `#AF3050`
- 금색: `#F2D27A` `#E8B54A`
- 노을: `#EFDFDF` `#DF9F8F` `#DF608F` `#E89AC0`
- 적·어두운 색: `#9060A8` `#6E4A6A` `#404050` `#302030` (순수 검정 없음)

**검수 방법**
1. 그림은 마스터 팔레트 색만으로 그린다 (`assets/art_src/palette/jei_master.gpl`, 제작 스크립트가 팔레트 밖 색을 막는다 — 섹션 8).
2. `#302030`보다 어두운 픽셀이나 순수 검정 외곽선이 있으면 실패.
3. 흑백 썸네일 검사로 섹션 3의 형태 규칙을 확인한다.
4. 사람이 손으로 고친 파일은 내보내기 전에 팔레트 밖 색이 없는지 다시 확인한다.

## 5. Character Design Direction

**음영 규칙** (사용자 결정 2026-10-28): 재질마다 팔레트에서 한 단계 어두운 색을 음영으로 쓴다 (청록 → 짙은 청록, 크림 → 돌색). 가장 어두운 `#302030`은 접지면·틈새·외곽선 예외에만 쓴다.

**크기** (개정 2026-10-28, 사용자 결정): 모든 게임 그림을 약 1.5배로 키운다 (게임 해상도 360x640은 그대로). 충돌 크기와 레벨 간격은 레벨 디자인 단계에서 다시 정하며, 그때까지 그림이 판정보다 크다. 근거: Cat Isle 캐릭터 약 40~45px, Doloc Town 약 26px, 첫 제이 32px (같은 배율로 측정).

**제이** (최종 기준 그림 `assets/art/player/jei/default/reference.png`, 40x52 칸, 캐릭터 36x49, 충돌 16x24 임시) — 사용자가 준 AI 컨셉 그림을 원래 도트로 되돌려 그대로 쓴다 (사용자 결정 2026-10-28, 에이전트가 그린 v1~v4는 폐기). 이 그림이 모든 캐릭터 그림의 기준이다.
- 빨간 후드 망토를 쓴 모습(후드를 씀), 검은 단발, 큰 갈색 눈과 흰 하이라이트, 볼터치, 벌린 입.
- 흰 소매 블라우스 + 진한 갈색 원피스, 갈색 신발. 망토는 몸을 감싸고 양옆으로 퍼진다.
- 검은 1px 외곽선, 재질별 한두 단계 음영, 색은 `jei_character.gpl` 32색.
- 정면에 가까운 구도 (왼쪽 이동은 `flip_h`).
- 표정 3종: 기본, 피격(`> <`), 능력 사용(입 벌림).
- 다른 동작·능력 망토는 이 그림의 몸·얼굴을 그대로 두고 필요한 부분만 바꿔 만든다.
- **능력 표시** (사용자 결정 2026-10-28): 능력을 얻으면 **망토의 모양과 색**이 바뀐다 — 불덩이 = 주황 망토 + 둥근 불꽃 끝단, 높이 점프 = 허리까지 오는 짧은 파란 망토 + 별, 활공 = 넓은 날개형 분홍 망토 + 꽃잎 끝단. 몸·얼굴은 4세트 공통이고 망토만 바뀐다 (4세트, 각 세트 시트 따로).

**적** (스프라이트 24x24, 색은 보라 `#9060A8` + 음영 `#6E4A6A` — 개정 2026-10-28)
- 걷는 적: 보라 반원 몸통(21x15) + 뿔 1개(크림, 끝은 뾰족).
- 점프하는 적: 보라 물방울(15x18) + 남색 용수철 다리. 뛰기 전 몸을 눌러 예고하며 주황 반짝임으로 표시.
- 나는 적: 보라 원(12x12) + 크림 삼각 날개 2장 + `#302030` 외곽선.
- 공통 눈: 크림 바탕에 남색 점, 비스듬한 눈썹. 화난 얼굴이지만 귀엽게 (1.5배 크기).

**보스 가시 두더지** (스프라이트 72x60, 충돌은 레벨 디자인에서 다시 정함 — 개정 2026-10-28)
- `#8A5A3C` 반구 몸통 + 크림 배·얼굴 + 등의 부채꼴 가시(크림, 끝은 `#9060A8`, 남색 외곽선) + 크림 삽 앞발 2개.
- 예고 포즈는 실루엣으로 구분: 흔들기 = 좌우 1px 진동, 웅크리기 = 높이 -25%, 부풀기 = 가시 펼침.
- 그림이 커지므로 돌진·찍기 회피 거리를 레벨 디자인·밸런스 테스트에서 다시 맞춘다.

**애니메이션 프레임** (스트립 1줄 = 동작 1개)

| 대상 | 동작별 프레임 수 |
|---|---|
| 제이 | idle 2, run 4 (여유 있으면 6), jump 1, fall 1, ability 2, hurt 1 (`> <`, 사용자 결정 2026-10-28). 흰색 깜빡임은 셰이더 |
| 적 | walk/move 2~4, defeated 3 (납작 → 연기) |
| 보스 | idle 2, shake 2, crouch 2, puff 3, roll 4, jump 2, dazed 2 (+별 이펙트), hurt 1, dust 4 (별도 24x24) |
| 아이템·깃발 | idle 2~4 |

- 합계 약 50프레임 (제이 4세트 포함 시 더 늘어남). 에이전트가 Aseprite 스크립트로 그리는 범위 (섹션 8).

## 6. Environment Design Language

**레이어**

| 레이어 | 내용 | 패럴랙스 |
|---|---|---|
| L0 | 하늘 그라데이션 | 고정 |
| L1 | 둥근 구름 | 0.1, 느리게 흐름 |
| L2 | 먼바다, 등대·섬 실루엣 | 0.25 |
| L3 | 항구 건물 (청록 기와, 줄무늬 차양) | 0.5 |
| L4 | 플레이 영역 | 1.0 |
| L5 | 전경 (밧줄, 계선주, 물결) | 1.15, y 280 아래 40px 띠에만 |

- 배경(L2~L3)은 밝은 쪽 팔레트만: 기와 `#AFDFDF`, 벽 `#EFFFFF`/`#E3DDD2`, 차양 `#F0A040`/`#DF9F8F` 줄무늬. 등대 줄무늬도 `#DF9F8F` 복숭아 (게임 화면의 진한 빨강은 제이 전용).
- 진한 `#50AF9F`, `#D2373F`는 L4 전용. 배경 빨강은 줄무늬·직사각형·둥근 형태만.
- L5는 캐릭터 위를 가리지 않는다.

**지형 매핑**
- 바닥: Cat Isle식 돌 부두. 윗면 `#F6EEE4` 2줄, 몸통 `#E3DDD2`, 24px 간격 이음매 `#BDB4A8`. 아래 물에는 `#80DFFF` 물결 문양(세이가이하).
- 떠 있는 블록: 청록 기와 덩어리. 몸통 `#50AF9F`, 윗면 크림 2줄, 아래 음영 `#408F9F`.
- 블록 크기가 제각각이므로 24px 타일 단위(원본 72x72, 9-slice 여백 8px — 높이 16px 블록도 깨지지 않게)로 만들어 나중에 타일맵으로 바로 옮긴다 (개정 2026-10-28: 1.5배).
- 갈색 나무(`#C98A5A`/`#8A5A3C`)는 L4에서 불타는 벽 전용. 배경 부두 기둥은 `#BDB4A8` 쪽으로 채도를 낮춘다.

**질감**
- 단색 덩어리 + 음영 1톤 + 윗면 하이라이트 1줄. 디더링·그라데이션·노이즈 질감 없음 (L0 하늘 제외).
- 배경 디테일은 4px 이하 단위로 L4보다 잘게.

**소품 밀도** (화면 폭 360px 기준)
- L1: 건물 1채, 갈매기 1~2. L2: 건물 2채, 빨래줄, 차양. L3: 등대 1, 절벽 바위, 노을 구름 많이.
- 보스: 동굴 입구와 등불 2개뿐. 아레나 바닥 위는 비운다.
- 공통: 발판 윗면에서 위로 24px 안(캐릭터가 서는 높이)에는 대비 높은 배경 소품을 두지 않는다.

**상호작용 오브젝트**
- 불타는 나무벽: 세로 판자 + 못 자국 + 바닥 쪽 그을음 `#5A3A2C` + 작은 불꽃 그림 표지판.
- 가시: 24px 폭에 삼각형 3개(각 8px). 몸통 `#E3DDD2`, 끝 `#9060A8`, `#302030` 외곽선. 보스가 떨어뜨리는 가시(16x28)도 같은 문법, 아래로 향함.
- 체크포인트: 남색 기둥(24x48) + 둥근 꼭지. 비활성 크림 깃발, 활성 금색 `#E8B54A` + 반짝임 2프레임.
- 골 깃발: 24x72, 금색 메달 + 빨간 리본 깃발. 체크포인트보다 크게.
- 보너스 하트: 24x24 프레임 안에 금색 통통한 하트 18x18. 위아래 1px 흔들림 + 반짝임.

**글 없이 이야기 전하기 (8~12세)**
- 레벨이 진행될수록 두더지 흙더미와 땅굴 구멍이 늘어나 보스를 예고한다.
- 배경 고양이 주민(Cat Isle 오마주): L1에서는 산책, L3에서는 창문 뒤에 숨는다.

## 7. UI/HUD Visual Direction

art-director 초안 + ux-designer 검토. 둘이 부딪힌 두 곳은 사용자가 정했다 (2026-10-28, 아래 "결정된 충돌").

**HUD (게임 뷰 360x320)**
- HUD는 2개뿐: 왼쪽 위 하트, 오른쪽 위 목숨 "x 3". 화면 가장자리에서 8px 띄운다.
- 하트·목숨 아이콘은 `#302030` 외곽선 2px 필수 (1px 금지). 받침 띠는 두지 않는다.
- 빈 하트: 남색 테두리 2px 이상, 찬 하트와 실루엣 크기가 같다.
- 능력·체크포인트처럼 게임 안에 보이는 정보는 게임 속에서 보여준다 (제이의 망토, 금색 깃발). HUD에 다시 띄우지 않는다.

**글꼴** (번들 한글 픽셀 폰트)
- 추천 Galmuri11 (갈무리, 한글 지원), 대안 둥근모꼴(NeoDunggeunmo). 라이선스(SIL OFL 1.1로 알려짐)는 NOT VERIFIED — 번들 전에 저장소 LICENSE를 확인한다.
- 기준 크기의 정수배만, 앤티에일리어싱 끔.
  - 1x 11px: 숫자 전용 ("x 3" 등). 한글은 1x로 쓰지 않는다 (받침이 뭉개짐).
  - 2x 22px: 한글 최소 크기, 버튼 글자.
  - 3x 33px: 리본 제목, "클리어!".
- 글자색 3가지: 크림 패널 위 `#302030`, 남색 버튼 위 크림, 강조 `#D2373F`. 리본(빨강) 위 크림 글자는 굵게 + 남색 그림자 1px (대비 4.2:1이라 큰 글씨 전용).
- 문구는 짧게: "다시 하기", "계속하기".
- 실제 기기에서 한글 가독성을 확인한다.

**아이콘**
- 평면 픽셀 아이콘, 팔레트 색만, 음영 1톤, 검은 외곽선 없음.
- 조작 버튼은 영어 대신 아이콘: 이동 = 크림색 통통한 삼각 화살표, 점프 = 굵은 위쪽 화살표(남색·크림만 — 하늘색 높이 점프 아이콘과 구분), 능력 = 지금 가진 능력 아이콘(섹션 4 불꽃 / 하늘색 화살표 / 분홍 날개, 없으면 흐린 빈 원), 메뉴 = 일시정지 `||`.
- 한글 라벨 보조: 레벨 1을 처음 할 때만 버튼 아래에 한글 라벨(22px)을 보여주고, 이후에는 아이콘만 (사용자 결정 2026-10-28).
- UI 상태는 색만으로 구분하지 않는다 (아이콘 모양으로도 표시).

**터치 조작부 (하단 360x320)**
- 배경: 크림 `#F6EEE4` 단색 판 (사용자 결정 2026-10-28). 윗변에 `#E3DDD2` 2px 띠로 게임 뷰와 나눈다. 게임 화면의 연장으로 보이지 않도록 하단에는 배경 그림·캐릭터·움직이는 장식을 넣지 않는다.
- 버튼: `#302030` 둥근 사각, 반경 8px, 아래쪽 4px는 `#404050`로 두께 표현.
  - 누름: 4px 내려가고 두께가 사라짐 + 크림 테두리 2px. 색만 바꾸지 않는다. 손을 떼면 즉시 원상태. 반응 지연 0프레임.
  - 비활성: `#BDB4A8` 바탕 + 아이콘 50%.
- 능력 버튼: 능력이 없으면 비활성 + 빈 원. 능력을 얻으면 테두리·아이콘이 능력 색으로 바뀌고 1회 통통 튄다.
- 터치 크기: 최소 64x64, 버튼 사이 12px 이상. MENU(작은 알약, 오른쪽 위 구석)는 다른 버튼과 16px 이상 떨어뜨린다. 누르는 영역은 그림보다 작지 않다.

**메뉴**
- 크림 둥근 패널 + 빨간 리본 제목 + 남색 알약 버튼 (280x72, 2x 글자).
- 레벨 선택: 금색 메달(빨간 끈, 메달 안에 숫자 1~3), 보스가 있는 레벨 3은 메달 안에 가시 두더지 얼굴. 세이브가 없어 잠금 상태는 그리지 않는다 (세이브가 생기면 돌색 `#BDB4A8` + 자물쇠 모양).

**클리어 / 게임 오버**
- 클리어!: 게임 뷰 위 금색 방사형 빛, 빨간 리본에 3x "클리어!", 색종이, 금색 메달 하나가 내려와 박힌다.
- 게임 오버: `#302030` 60% 막 + 크림 패널 + 리본 "다시 해볼까?"(임시 문구) + 졸린 제이 + 버튼 "다시 하기". 빨간 화면·검정 화면 금지.

**UI 애니메이션**
- 짧게 0.1~0.25초, 등장 연출은 0.3초 이하. 통통하게: 1.1배까지 갔다가 1.0. 이동은 2px 단위.
- 탭하면 바로 건너뜀. 클리어 연출은 0.5초 뒤부터 탭으로 넘김.
- 반짝임은 초당 3회 미만. 화면 흔들림·번쩍임은 설정에서 끌 수 있게 한다 (설정 화면이 생길 때).

**결정된 충돌**
- HUD 가독성: art-director는 받침 없이 1px 그림자, ux-designer는 금색 하트가 `#BFEFFF` 위에서 대비 약 1.5:1(기준 3:1)이라 외곽선 2px 또는 받침 띠를 요구. → 남색 외곽선 2px로 결정.
- 하단 배경: art-director는 크림 판, ux-designer는 게임과 착각하지 않게 남색 판을 권고. → 크림 판으로 결정하고, ux 우려는 경계 띠 + 하단에 게임 그림 금지 규칙으로 보완.
- 원칙: 픽셀 폰트의 멋보다 읽기가 먼저. 버튼 글자가 길면 크기를 줄이지 말고 글자 수를 줄인다.

## 8. Asset Standards

art-director 초안 + technical-artist 제약 (2026-10-28).

**프레임 배치**
- 스트립 1개 = 동작 1개, 가로 1줄, 여백·간격 0 (`SheetFrames.add_strip`이 x축으로만 자름).
- 한 스트립 안의 프레임 크기는 모두 같다. 파일 폭 = 프레임 폭 x 프레임 수.
- 발 위치(바닥선)는 모든 프레임에서 같은 y, 몸 중심은 같은 x.
- 기본은 오른쪽을 본다. 왼쪽은 런타임 `flip_h`.
- 피격 흰색 깜빡임은 셰이더로 처리한다. 제이만 피격 표정용 `hurt` 1프레임을 따로 그린다 (섹션 5).

**에이전트 제작 순서** (사용자 결정 2026-10-28: AI 이미지 생성은 쓰지 않고, 에이전트가 Aseprite를 Lua 스크립트로 다뤄 직접 그린다. Aseprite 경로는 `project.yaml`의 `tools.aseprite`)
1. 에셋 명세(`design/assets/specs/`)에서 크기·프레임·색을 읽는다.
2. Lua 스크립트를 `tools/art/[대상].lua`로 쓴다. 공용 도우미 `tools/art/lib.lua`로 팔레트를 불러오고, 팔레트 밖 색을 쓰면 스크립트가 실패로 멈춘다.
3. 배치 모드로 실행: `Aseprite.exe -b --script-param out=... --script tools/art/[대상].lua` → `.aseprite` 원본(`assets/art_src/`)과 가로 스트립 PNG(`assets/art/`)를 함께 만든다.
4. 8배 확대 미리보기와 흑백 썸네일로 에이전트가 직접 검사한다 (섹션 1 그림 검수 기준, 섹션 3 형태 규칙).
5. 게임에서 실행한 스크린샷을 사용자에게 보여 주고 확인받는다.
6. `.tres`의 `frame_size`, `frame_count`, `fps`, `loop`를 실제 파일과 맞춘다.
- 스크립트는 저장소에 남긴다. 색이나 모양을 고칠 때 스크립트를 고쳐 다시 실행하면 같은 그림이 다시 만들어진다. 사용자가 `.aseprite`를 열어 손으로 고친 경우에는 그 파일이 원본이 되고, 스크립트를 다시 돌리기 전에 확인한다.
- 큰 배경(L2~L3)은 스크립트로 그리면 단순해질 수 있다. 스크린샷을 보며 여러 번 다듬는다.

**엔진 제약** (Godot 4.7, Compatibility, 모바일)
- 텍스처 import: `compress/mode` Lossless 유지 (VRAM 압축 ETC2/ASTC는 색이 깨짐; 프로젝트의 `import_etc2_astc`는 VRAM 압축 텍스처에만 적용되어 이 그림들과 무관), mipmaps 끔, `fix_alpha_border` 켬, `premult_alpha` 끔. 필터는 프로젝트 기본 Nearest를 따른다.
- 시트당 최대 2048x2048 (저가 기기 보장 기준; 엔진 문서로는 NOT SOURCEABLE, 일반 GLES 3.0 기준).
- 아틀라스: 지금은 쓰지 않는다. 드로우 콜 문제가 측정되면 합친다 (그때 `add_strip`의 y 오프셋 처리 필요).
- 패럴랙스: `Parallax2D` 노드, `repeat_size.x` = 이미지 폭. 화면 비율이 넓은 폰에서 화면이 360보다 넓어지므로 모든 레이어는 이음매 없이 반복되어야 하고, L0 하늘은 세로 방향 그라데이션만. 4.5~4.7 변경 여부는 NOT SOURCEABLE — 구현 때 확인.
- 픽셀 떨림 방지: `rendering/2d/snap/snap_2d_transforms_to_pixel` 검토 (구현 때 확인, NOT SOURCEABLE).
- 폰트(Galmuri11, SIL OFL 1.1 확인됨 — github.com/quiple/galmuri): antialiasing None, hinting None(4.7에서 기본값이 바뀌었으므로 명시), subpixel_positioning Disabled, MSDF·mipmaps 끔. 크기 11/22/33만.
- 텍스처 메모리 예산 (사용자 결정 2026-10-28): 레벨 1개 로드 기준 16MB 이하, 전체 상주 32MB 이하. 근거: 720x320 RGBA 레이어 1장 약 0.9MB, 6장 약 5.5MB, 캐릭터·UI 1MB 미만.

**결정된 충돌**
- 제이 능력 색: technical-artist는 색 바꾸기 셰이더(끈 기본색이 피부색과 같아 표시용 키 색 필요, 깃은 음영 없이)를 제안. → 사용자는 능력별 시트 4세트를 선택 (작업량은 늘지만 셰이더와 키 색 규칙이 필요 없고 깃 음영 가능). 섹션 5 갱신.

## 9. Reference Direction

**1. Cat Isle (주 레퍼런스, Steam)**
- 가져올 것 (스타일 규칙만): 연한 하늘·물 위의 단색 덩어리 + 음영 1톤 / 청록 기와와 줄무늬 차양 / 돌 부두 윗면의 밝은 1줄, 물결 문양과 수면 반사 / 분홍·복숭아 노을과 겹겹이 쌓인 둥근 구름 / UI: 크림 둥근 패널, 남색 글자, 강조 단어 하나만 빨강.
- 큰 일러스트(게임 오버의 졸린 제이, 메뉴 일러스트 등 게임 화면 밖 그림)에 한해 Cat Isle 대화 초상화식 두꺼운 크림색 테두리를 허용한다 (사용자 결정 2026-10-28). 게임 속 캐릭터·오브젝트에는 섹션 1의 외곽선 규칙이 그대로 적용된다.
- 복사 금지: 고양이 캐릭터와 초상화, 로고, 한자 간판(魚市場, 猫島 등), 특정 건물(어시장, 대형 닻 구조물, 어항 오브젝트), 실제 UI 그림과 손가락 커서. 배경 고양이 주민(섹션 6)은 새로 디자인하며 Cat Isle 고양이와 실루엣·무늬가 겹치면 안 된다.
- 제작 규칙: Cat Isle 스크린샷을 픽셀 단위로 따라 그리거나 대고 그리지 않는다 (스타일 규칙만 가져온다). 그림에 고양이 캐릭터·한자 간판·닻 구조물을 넣지 않는다. 그림 제작은 에이전트가 Aseprite 스크립트로 한다 (섹션 8).

**2. Super Mario Bros. 3**
- 가져올 것: 짧은 레벨의 도입 → 변형 → 응용 구조, 점프 감각, 발판 블록은 배경보다 큰 덩어리로 윗면을 확실히 구분.

**3. Shovel Knight** (세부 기법 NOT VERIFIED)
- 가져올 것: 복잡한 화면에서 위험물이 읽히는 방식 — 배경 레이어는 명도 범위를 좁히고, 가시와 적은 가장 밝은 색과 가장 어두운 색을 둘 다 갖는다. 원칙 1과 섹션 3 흑백 썸네일 검사의 기준.
